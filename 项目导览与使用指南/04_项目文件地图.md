## 2. API

### `apps/api/app/main.py`

负责：

- FastAPI 实例和 lifespan。
- CORS。
- `/healthz`。
- 创建和读取会话。
- 提交 Agent 消息。
- SSE 事件流。
- Trace 查询。
- 工具目录。
- 10 个直接 Analytics API。

增加一个公开 API 时，需要：

1. 在 `schemas.py` 或 Analytics Schema 中定义请求。
2. 在 `main.py` 增加路由。
3. 指定 `response_model`。
4. 增加测试和本指南中的 API 表。

### `apps/api/app/run_service.py`

负责：

- 将用户消息写入 `app.chat_messages`。
- 创建 `app.agent_runs`。
- 在 FastAPI 后台任务中执行 LangGraph。
- 保存节点、工具和事件。
- 生成 SSE 事件。
- 保存最终助手消息。
- 异常时保存失败信息。

这是当前执行编排核心。生产化时最可能被任务队列 Worker 替换。

### `apps/api/app/schemas.py`

包含会话、消息、运行接受结果和 Trace 的 Pydantic 模型。

## 3. Agent

### `packages/agent_runtime/state.py`

定义 `AgentState`：

- 身份：run、session、user。
- 请求：query、time_range、entity_filters。
- 决策：intent、plan。
- 证据：analytics_results、retrieved_chunks。
- 输出：draft_answer、model_used。
- 控制：budgets、approval、warnings、errors。

### `packages/agent_runtime/workflow.py`

包含：

- 日期、卖家 ID、最小样本量正则。
- 10 类意图路由。
- 每个意图的计划。
- 工具调用组合。
- 知识检索与注入过滤。
- Evidence Gate。
- 确定性模板。
- Ollama 生成和输出安全门。
- LangGraph 构建和 PostgreSQL Checkpoint。

新增 Agent 能力通常需要修改：

1. `route_intent`
2. `build_plan`
3. `run_analytics`
4. 测试
5. Web 场景库
6. 文档

## 4. Analytics

### `packages/analytics/schemas.py`

所有工具参数在此定义。它保证：

- 日期结束不早于开始。
- `group_by` 只能使用 allowlist。
- top-k 和样本量有边界。
- 卖家 ID 格式受控。
- 评论分数和返回数量有上限。

### `packages/analytics/service.py`

真正执行 SQL 的位置。所有查询：

- 使用绑定参数。
- 只查询 MART。
- 返回统一 `MetricResult`。
- 明确指标定义、筛选条件、新鲜度和警告。

### `packages/analytics/tools.py`

把 Service 方法注册成 Agent 工具。这里定义：

- 稳定工具名。
- 给 Agent/开发者看的描述。
- Pydantic 输入模型。
- 权限级别。
- Handler。

### `packages/tools/registry.py`

Tool Registry 是工具控制面：

- 拒绝重复工具名。
- 拒绝未知工具。
- 调用前校验输入。
- READ、GENERATE、PERSIST、EXTERNAL_WRITE 分级。
- 当前直接拒绝 PERSIST 和 EXTERNAL_WRITE。

## 5. 数据库

### `db/migrations/001_initial.sql`

创建：

- pgvector、pgcrypto。
- `raw`、`staging`、`mart`、`app`、`knowledge`、`eval` Schema。
- 业务数据表。
- 会话、运行、事件、工具、审批、产物表。
- 知识文档和片段。
- 评测预留表。

### `db/staging/create_staging.sql`

使用普通 View：

- 将文本转为 timestamp、integer、numeric。
- 将空字符串转为 NULL。
- 连接葡萄牙语—英语类别翻译。
- 保留 RAW 原貌。

### `db/marts/refresh_marts.sql`

创建七个物化视图：

1. `mart_order_fulfillment`
2. `mart_seller_order_fulfillment`
3. `mart_category_order_fulfillment`
4. `mart_review_analysis_base`
5. `mart_payment_analysis_base`
6. `mart_seller_performance_monthly`
7. `mart_category_performance_monthly`

核心原则是先按目标粒度聚合，再连接订单，避免笛卡尔放大。

## 6. RAG 和模型

### `packages/retrieval/service.py`

当前检索方法：

1. 领域 Query Expansion 与中文 n-gram。
2. PostgreSQL `websearch_to_tsquery` + `ILIKE` 词法候选。
3. 384 维 `local_hash` + pgvector cosine 候选。
4. Weighted RRF 融合 FTS 与 Vector 排名。
5. 最多返回 5 个片段并记录检索日志。
6. 检查可能的 Prompt Injection。

### `packages/model_gateway/ollama.py`

Ollama 参数：

- `/api/chat`
- `stream=false`
- `think=false`
- `keep_alive=10m`
- `num_ctx=6144`
- `num_predict=1200`
- 默认温度 0.1；工作流合成显式使用 0.0
- `trust_env=False`

## 7. Web

- 健康状态。
- 七个预置场景。
- 会话复用。

## 9. 修改需求到文件的映射

| 需求 | 优先修改 |
|---|---|
| 新增指标 | Analytics Schema → Service → Tools → Test |
| 新增 Agent 意图 | workflow route/plan/run → Test → Web |
| 新增知识 | `data/knowledge_seed` → `build_knowledge.py` |
| 新增 API | `main.py` → Schema → OpenAPI/Test |
| 改模型 | `.env`、Model Gateway |
| 改数据粒度 | SQL MART → Service → Gold Test |
| 改页面场景 | `App.tsx`、`styles.css` |
| 改权限 | Tool Registry、安全测试 |
| 增加审批 | approvals 表、API、Graph interrupt/resume、Web |
| 替换正式语义 Embedding | Provider、全量重建向量、索引、混合权重、盲测 |

## 10. 生成目录与源码目录的区别

不应手动编辑：

- `.runtime`
- `data/postgres`
- `models/ollama`
- `apps/web/dist`
- `__pycache__`
- `*.egg-info`

应通过源码或脚本重建这些目录。
