# 术语与指标口径

## 1. Agent 相关术语

| 术语 | 含义 |
|---|---|
| Agent | 根据输入选择步骤、调用工具、维护状态并产生结果的系统 |
| Intent | 当前问题被识别出的分析意图 |
| Plan | 由意图映射出的受约束步骤列表 |
| Tool | 带固定名称、输入 Schema、权限和 Handler 的能力 |
| State | LangGraph 节点之间传递的结构化状态 |
| Evidence Gate | 在生成答案前检查结构化证据是否存在 |
| Checkpoint | 保存 Graph 状态以支持可追踪和未来恢复 |
| Trace | 一次运行的节点、工具、事件和状态记录 |
| Fallback | 模型不可用或不合格时使用确定性模板 |
| Guardrail | 参数、权限、证据和输出限制 |

## 2. 数据层术语

| 术语 | 含义 |
|---|---|
| RAW | 原始 CSV 的文本镜像 |
| STAGING | 类型转换和标准化视图 |
| MART | 面向分析粒度的物化视图 |
| Grain | 一行数据代表的业务粒度 |
| Materialized View | 将查询结果实际存储、需要刷新或重建的视图 |
| Order Grain | 一行一个订单 |
| Order-Seller Grain | 一行一个订单与卖家组合 |
| Order-Category Grain | 一行一个订单与类别组合 |
| Order-Payment-Type Grain | 一行一个订单与支付方式组合 |

## 3. 订单量

定义：

```sql
count(DISTINCT order_id)
```

为什么去重：一个订单可能有多个商品、卖家、支付序列或评论。

## 4. GMV 代理值

定义：

```text
sum(item price)
```

它不包括：

- 财务确认规则。
- 退款和退货后的净额。
- 税费。
- 会计收入确认。

因此文档统一称为“GMV 代理值”或“商品金额代理值”。

## 5. 平均订单商品金额

订单 MART 已先按订单聚合商品金额：

```text
avg(order.item_value)
```

不是直接对订单明细的商品行求平均。

## 6. 延期订单

```text
is_late = delivered_at > estimated_at
```

如果实际送达或预计送达日期缺失，`is_late=NULL`，不进入延期率分母。

## 7. 延期率

```text
延期订单量
-------------------------------
实际送达和预计送达日期都存在的订单量
```

代码使用：

```sql
count(DISTINCT order_id) FILTER (WHERE is_late)
/
count(DISTINCT order_id) FILTER (WHERE is_late IS NOT NULL)
```

## 8. 平均延期天数

只对 `is_late=true` 的订单计算：

```text
delivered_at - estimated_at
```

按时订单的 `late_days` 为 0，但在“平均延期天数”指标中会被 FILTER 排除。

## 9. 平均配送天数

```text
delivered_at - purchased_at
```

未送达订单为 NULL。

## 10. 延期与按时评分差

```text
平均评分(延期订单) - 平均评分(按时订单)
```

当前评分先在订单 MART 中对同一订单的评论求平均，再按配送组求平均。

该差异是相关性描述，不证明延期导致评分下降。

## 11. 运费占比

```text
freight_value
--------------------------------
item_value + freight_value
```

它是公开订单数据中的字段比例，不是承运商发票成本率。

## 12. 平均每单运费

```text
sum(freight_value) / count(DISTINCT order_id)
```

类别粒度中的订单可能跨类别重复出现，因此不能跨类别相加还原整体。

## 13. 订单状态异常

经营总览把以下两类作为异常观察分子：

```text
canceled + unavailable
```

这只是观察口径，不代表两者有同一根因。

## 14. 支付金额占比

```text
某支付方式 payment_value
-----------------------------
所有支付方式 payment_value
```

同一订单可以参与多个支付方式，所以支付方式的参与订单量不可直接相加。

## 15. 同行基线

卖家诊断中的 peer baseline：

1. 选定时间范围。
2. 每个卖家先计算延期率和平均评分。
3. 只保留至少 5 个订单的卖家。
4. 对卖家级指标求平均。

这是未按卖家订单量加权的描述性卖家均值，不是因果基准。

## 16. 数据新鲜度

Analytics 返回：

```sql
max(purchased_at)::date
```

当前公开数据新鲜度为 2018 年历史日期。它说明数据覆盖终点，不代表数据库刷新时间。

## 17. Knowledge Chunk

知识 Markdown 按标题层级和约 600 字符目标长度切分。每个片段保存：

- 文档 ID。
- 顺序。
- 标题路径。
- 内容。
- SHA-256 内容哈希。
- 粗略 token 数。
- FTS search_vector。
- 384 维 local_hash embedding。

## 18. FTS、Dense、RRF、Reranker

| 方法 | 当前状态 |
|---|---|
| PostgreSQL FTS | 已实现 |
| ILIKE 词法回退 | 已实现 |
| pgvector 扩展 | 已启用 |
| local_hash 向量 | 已实现，离线 fallback，不是语义模型 |
| 向量 HNSW 索引 | 已实现，`vector(384)` cosine |
| RRF 融合 | 已实现，默认 FTS 0.75 / Vector 0.25 |
| Cross-Encoder Reranker | 未接入 |

## 19. SSE

Server-Sent Events 是服务器向浏览器单向推送文本事件的协议。

当前事件包括：

- `run.queued`
- `run.started`
- `node.started`
- `node.completed`
- `tool.completed`
- `assistant.delta`
- `run.completed`
- `run.failed`
- `heartbeat`

当前 `assistant.delta` 通常包含完整最终答案，而不是一个 Token。

## 20. 权限等级

| 权限 | 含义 | 当前行为 |
|---|---|---|
| READ | 查询 MART、知识和 Trace | 允许 |
| GENERATE | 生成草稿或临时内容 | 数据结构已定义 |
| PERSIST | 保存正式产物 | Tool Registry 直接拒绝，等待审批实现 |
| EXTERNAL_WRITE | 修改外部系统 | 当前禁止 |
