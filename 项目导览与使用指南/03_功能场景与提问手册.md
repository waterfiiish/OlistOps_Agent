# 功能场景与提问手册

## 1. 如何写出容易得到可靠结果的问题

一个高质量问题最好包含：

```text
时间范围 + 分析对象 + 指标 + 样本门槛 + 希望的比较或输出
```

例如：

```text
分析 2018 年 1 月到 8 月各州的配送表现，
只保留订单量至少 100 的州，
比较延期率、平均配送天数和评分，并列出需要复核的地区。
```

尽量避免：

```text
看看哪里不好。
```

这种问题缺少时间、对象和指标，会落入 `mixed` 路由并使用默认全数据范围。

## 2. 日期识别规则

Agent 当前支持：

- 中文月份：`2018 年 7 月`
- 数字月份：`2018-07`
- 明确日期范围：`2018-01-01 到 2018-08-31`

如果没有识别到日期，默认范围为：

```text
2016-09-01 至 2018-08-31
```

所有结束日期按“包含结束日”解释，SQL 内部会转换为 `< end_date + 1 day`。

## 3. 样本门槛

以下表达可以识别最小订单量：

- `订单量不少于 20`
- `至少 100 单`
- `minimum 50`
- `min 30`

未指定时默认 `min_orders=20`。样本门槛用于卖家、类别、地区和部分运费排名，防止极小样本占据榜首。

## 4. 经营总览

### 路由关键词

`经营总览`、`运营总览`、`订单状态`、`取消率`、`取消`、`overview`、`canceled`、`unavailable`

### 会调用

- `olist.get_operations_overview`
- `olist.get_sales_summary`
- `olist.get_delivery_performance`
- 运营政策检索

### 推荐问题

```text
分析 2018 年全年的经营总览，包括订单状态、取消与不可用订单、
销售代理值、整体延期率和平均评分。
```

```text
比较 2017 年下半年和 2018 年上半年的订单状态结构，
重点说明取消与不可用订单占比，但不要推断库存原因。
```

### 注意

状态构成能告诉你“发生了什么”，不能单独说明“为什么发生”。取消、不可用、延期的根因需要库存、承运、工单或过程事件数据。

## 5. 月度趋势

### 路由关键词

`趋势`、`走势`、`月度`、`按月`、`trend`、`monthly`

### 会调用

- `olist.get_monthly_trend`
- 趋势分析政策检索

### 推荐问题

```text
分析 2017 年 1 月到 2018 年 8 月的月度趋势，
比较订单量、GMV 代理值、运费、延期率、平均配送天数和评分。
```

```text
按月查看 2018 年订单量与延期率走势，
指出可能是部分月份的数据，并保留每月合格履约分母。
```

### 注意

公开数据的首尾月可能不完整。月度变化是描述性趋势，不应自动解释为季节性、促销效果或长期增长。

## 6. 配送异常

### 路由关键词

`配送`、`延期`、`延迟`、`delivery`、`late`

### 会调用

- 卖家配送排名。
- 类别配送排名。
- 延期与按时订单评分比较。
- 配送政策检索。

### Gold 演示

```text
分析 2018 年 7 月的配送表现，找出延期率最高且订单量不少于 20
的卖家和商品类别，比较延期订单与按时订单的平均评分，并给出改进建议。
```

预期第一卖家：

```text
06a2c3af7b3aee5d69171b0e14f0ee87
订单量 71
延期订单 30
延期率 0.42254
```

## 7. 地区履约

### 路由关键词

`地区`、`区域`、`各州`、`州级`、`地域`、`geography`、`state`

### 会调用

- `olist.get_geography_performance`
- 按客户州分组的 `olist.get_freight_analysis`
- 区域政策检索

### 推荐问题

```text
比较 2018 年各州地区的履约表现，
订单量至少 100，找出延期率、平均配送天数和评分异常的区域。
```

```text
分析 2017 年各州运费占比和延期率是否同时偏高，
将事实与可能原因分开。
```

### 注意

地区按匿名客户州汇总，不包含精确地址。州级差异受到距离、商品组合和卖家分布等多因素影响。

## 8. 运费结构

### 路由关键词

`运费`、`物流成本`、`配送成本`、`freight`

### 会调用

- 整体运费结构。
- 类别运费结构。
- 运费政策检索。

### 推荐问题

```text
分析 2018 年运费结构，给出整体运费占比，
再找出订单量不少于 100 且运费占比较高的商品类别。
```

```text
比较 2018 年各州的平均每单运费、运费占比和延期率，
只保留至少 200 单的州。
```

第二个问题同时包含“各州”，因此地区路由优先，会生成州级履约和州级运费两个工具步骤。

### 注意

类别 MART 是订单—类别粒度。多类别订单可同时出现在多个类别中，不能把各类别订单量直接相加还原全站订单量。

## 9. 支付方式

### 路由关键词

`支付`、`付款`、`信用卡`、`分期`、`payment`、`boleto`、`voucher`

### 会调用

- `olist.get_payment_analysis`
- 支付分析政策检索

### 推荐问题

```text
分析 2018 年支付方式构成，比较支付金额占比、
参与订单量、平均最大分期数和平均支付序列数。
```

```text
比较 2017 和 2018 年信用卡、boleto、voucher 的支付金额结构。
```

### 注意

一个订单可以使用多种支付方式，因此不同支付方式的参与订单量不是互斥集合。支付金额也不是财务结算净额。

## 10. 低分评论

### 路由关键词

`差评`、`低分`、`投诉`、`review`

### 会调用

- `olist.search_review_samples`
- 低分评论处理规范检索

### 推荐问题

```text
分析 2018 年低分评论样本，结合处理规范总结可核查问题，
不要推断客户身份。
```

评论工具默认：

- `review_score <= 2`
- 最多返回 20 条
- 每条评论最多 280 个字符

样本用于展示证据，不用于估计低分评论总体占比。

## 11. 卖家诊断

只要问题中存在合法的 32 位十六进制卖家 ID，卖家诊断拥有最高路由优先级。

```text
诊断卖家 06a2c3af7b3aee5d69171b0e14f0ee87
在 2018 年的订单规模、商品金额、运费、延期率和评分，
并与至少 5 单的卖家基线比较。
```

卖家 ID 必须满足：

```regex
^[0-9a-f]{32}$
```

## 12. 销售摘要

### 路由关键词

`GMV`、`销售`、`客单价`、`sales`

### 推荐问题

```text
汇总 2018 年 1 月到 8 月已送达订单的订单量、
GMV 代理值、平均订单商品金额、运费占比和评分。
```

销售摘要不强制检索知识，因为主要输出是结构化指标。

## 13. 路由优先级

当前优先顺序为：

1. 合法卖家 ID。
2. 支付。
3. 地区。
4. 运费。
5. 趋势。
6. 经营总览。
7. 配送。
8. 评论。
9. 销售。
10. mixed。

例如“各州运费分析”会命中地区而不是通用运费，因此会同时调用地区履约和按客户州分组的运费工具。只写“运费分析”时才进入整体与类别运费路径。

> 上述最后一个例子提醒使用者：当前路由是确定性关键词规则，不是大模型 Tool Calling。复杂歧义问题应观察 Trace 中的 `intent` 和 `tool_name`。

## 14. 如何判断回答是否可信

至少检查：

- Trace 中是否调用了预期工具。
- 工具参数中的日期与 `min_orders` 是否正确。
- 报告是否显示分母或样本量。
- 延期率是否只基于合格日期订单。
- 是否存在 `K-xxx` 引用。
- 是否把“相关”误写成“因果”。
- `model_used` 是本地模型还是 `deterministic-template`。

## 15. 使用 run_id 复查

```text
GET /api/v1/runs/{run_id}/trace
```

Trace 包含：

- `run`：状态、意图、保存状态、警告、耗时。
- `steps`：每个 LangGraph 节点。
- `tool_calls`：工具名、权限、参数和结果摘要。
- `events`：SSE 使用的事件序列。
