# 从零安装、启动与使用

本文同时覆盖两种情况：

- 当前项目已经完整部署，只需要启动。
- 将项目复制到另一台 Windows 机器后从零初始化。

## 1. 当前机器最快启动方式

在项目根目录 `E:\Data\OlistOps_Agent` 打开 PowerShell：

```powershell
Set-Location E:\Data\OlistOps_Agent
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start.ps1
```

等待数秒后检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/healthz
```

健康结果应包含：

```text
status: ok
database: olistops / PostgreSQL 16.x / vector_enabled=true
model: qwen2.5:3b
```

然后打开：

- Web：<http://127.0.0.1:5173>
- Swagger：<http://127.0.0.1:8000/docs>

## 2. 从零部署的前置条件

### 必需

- Windows 10 或 Windows 11。
- PowerShell 5.1 或更新版本。
- Conda 命令可用。
- Node.js 与 npm 可用。
- 足够磁盘空间保存 Python、PostgreSQL、CSV 和模型。
- 能访问 Kaggle 数据下载地址和 Ollama 发布地址。

### 推荐

- NVIDIA GPU，8GB 显存可流畅运行当前 3B 模型。
- 16GB 或更多内存。
- 约 10GB 以上项目可用空间。

GPU 不是数据库和确定性模板的必需条件。没有可用模型时，Agent 会回退到确定性报告模板。

## 3. 一键初始化

从项目根目录执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\bootstrap.ps1
```

脚本会：

1. 在 `.runtime\conda` 创建项目专用 Conda Prefix。
2. 安装 Python 3.12、PostgreSQL 16、pgvector 和 pip。
3. 安装 Python 项目与开发依赖。
4. 安装前端 npm 依赖。
5. 初始化项目内 PostgreSQL 集群。
6. 下载 9 份 Olist CSV。
7. 导入 RAW、创建 STAGING、重建 MART。
8. 生成数据质量报告。
9. 导入项目模拟知识库。
10. 下载便携 Ollama Windows 运行时。

可选参数：

```powershell
# 已有数据，不重新导入
.\scripts\bootstrap.ps1 -SkipData

# 暂时不安装 Ollama
.\scripts\bootstrap.ps1 -SkipOllama

# 两项都跳过
.\scripts\bootstrap.ps1 -SkipData -SkipOllama
```

## 4. 首次拉取模型

`bootstrap.ps1` 下载 Ollama 程序，但不会自动拉取大模型。先启动：

```powershell
.\scripts\start.ps1
```

然后：

```powershell
$env:OLLAMA_HOST = 'http://127.0.0.1:11434'
$env:OLLAMA_MODELS = (Resolve-Path .\models\ollama)
.\.runtime\ollama\ollama.exe pull qwen2.5:3b
```

检查模型：

```powershell
.\.runtime\ollama\ollama.exe list
.\.runtime\ollama\ollama.exe ps
```

项目中还可以保留其他模型。实际使用哪个模型由 `.env` 中的 `OLLAMA_MODEL` 决定。

## 5. 服务构成和端口

`scripts\start.ps1` 会启动四个项目内服务：

| 服务 | 端口 | 启动方式 |
|---|---:|---|
| PostgreSQL | 55432 | `.runtime\conda` 中的 `pg_ctl` |
| Ollama | 11434 | `.runtime\ollama\ollama.exe serve` |
| FastAPI | 8000 | Uvicorn |
| React Web | 5173 | Vite |

服务只绑定 `127.0.0.1`，默认不会监听局域网或公网。

日志位于：

```text
.runtime/logs/api.out.log
.runtime/logs/api.err.log
.runtime/logs/web.out.log
.runtime/logs/web.err.log
.runtime/logs/ollama.out.log
.runtime/logs/ollama.err.log
data/postgres.log
```

## 6. 使用 Web 界面

打开 <http://127.0.0.1:5173>。

页面分为：

1. 系统状态卡：数据库、pgvector 和模型状态。
2. 分析场景库：七个预置业务场景。
3. 自然语言输入区。
4. 实时 Trace 区。
5. 最终 Markdown 报告区。

推荐体验顺序：

1. 经营总览。
2. 月度趋势。
3. 配送异常。
4. 地区履约。
5. 运费结构。
6. 支付方式。
7. 低分评论。

同一页面生命周期内会复用一个 `session_id`，每次运行产生新的 `run_id`。当前 Agent 仍以本次问题作为主要路由输入，不应假设它已经实现完整的跨轮指代消解。

## 7. 直接调用 API

### 7.1 Python 推荐方式

Python/httpx 会正确发送 UTF-8 中文，并且 `trust_env=False` 可以避免系统代理错误拦截 localhost。

```python
import time
import httpx

query = "分析 2018 年的经营总览、取消订单、GMV 代理值和整体延期率。"

with httpx.Client(
    base_url="http://127.0.0.1:8000",
    timeout=180,
    trust_env=False,
) as client:
    session = client.post(
        "/api/v1/sessions",
        json={"title": "API demo"},
    ).json()

    accepted = client.post(
        f"/api/v1/sessions/{session['id']}/messages",
        json={"content": query},
    ).json()

    run_id = accepted["run_id"]
    while True:
        trace = client.get(f"/api/v1/runs/{run_id}/trace").json()
        if trace["run"]["status"] in {"completed", "failed"}:
            break
        time.sleep(0.25)

    print(trace["run"]["intent"])
    print([item["tool_name"] for item in trace["tool_calls"]])
```

### 7.2 PowerShell 中文 UTF-8 方式

Windows PowerShell 5.1 直接把字符串传给 `-Body` 时可能使用非 UTF-8 编码。应显式发送 UTF-8 字节：

```powershell
$payload = @{
    title = 'PowerShell UTF-8 demo'
} | ConvertTo-Json

$session = Invoke-RestMethod `
    -Method Post `
    -Uri 'http://127.0.0.1:8000/api/v1/sessions' `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([Text.Encoding]::UTF8.GetBytes($payload))

$message = @{
    content = '分析 2018 年支付方式的金额占比和平均分期数。'
} | ConvertTo-Json

$accepted = Invoke-RestMethod `
    -Method Post `
    -Uri "http://127.0.0.1:8000/api/v1/sessions/$($session.id)/messages" `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([Text.Encoding]::UTF8.GetBytes($message))

$accepted
```

### 7.3 直接调用确定性指标

```powershell
$body = @{
    start_date = '2018-01-01'
    end_date = '2018-08-31'
    group_by = 'customer_state'
    min_orders = 100
    top_k = 10
    delivered_only = $true
} | ConvertTo-Json

Invoke-RestMethod `
    -Method Post `
    -Uri 'http://127.0.0.1:8000/api/v1/analytics/freight-analysis' `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

## 8. SSE 事件流

提交消息会返回：

```json
{
  "run_id": "...",
  "session_id": "...",
  "status": "queued",
  "events_url": "/api/v1/runs/.../events"
}
```

浏览器可以使用：

```javascript
const stream = new EventSource(eventsUrl);

stream.addEventListener("tool.completed", (event) => {
  console.log(JSON.parse(event.data));
});

stream.addEventListener("assistant.delta", (event) => {
  console.log(JSON.parse(event.data).content);
});
```

事件流支持 `?after=<sequence>`，可从某个已接收序号之后继续读取。

## 10. 停止服务

```powershell
.\scripts\stop.ps1
```

停止脚本只处理端口 8000、5173、11434 上与当前项目路径匹配的进程，并通过 `pg_ctl -m fast` 停止项目内 PostgreSQL。

## 11. 不应提交或分享的内容

- `.env`
- `data/raw`
- `data/postgres`
- `.runtime`
- `models`
- 普通日志中的潜在运行数据
- 任何真实 API Key 或 Kaggle 凭据
