# 运维、排错与数据重建

## 1. 标准排查顺序

遇到问题时按以下顺序检查：

1. 项目路径是否正确。
2. 端口是否监听。
3. `/healthz` 返回内容。
4. PostgreSQL 状态。
5. Ollama 模型列表。
6. API/Web/Ollama/PostgreSQL 日志。
7. 直接 Analytics API 是否成功。
8. Agent Trace 中失败节点。

不要一开始就删除数据库或重装环境。

## 2. 服务状态

```powershell
Get-NetTCPConnection -State Listen -LocalPort 55432,11434,8000,5173
```

数据库：

```powershell
.\.runtime\conda\python.exe scripts\postgres_runtime.py status
```

模型：

```powershell
$env:OLLAMA_HOST = 'http://127.0.0.1:11434'
.\.runtime\ollama\ollama.exe list
.\.runtime\ollama\ollama.exe ps
```

健康：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/healthz
```

## 3. 健康状态含义

### `status=ok`

数据库可连接，pgvector 已启用，Ollama 可访问且模型列表可读取。

### `status=degraded`

常见原因：

- PostgreSQL 不可用。
- Ollama 不可用。
- 模型 API 超时。

数据库失败时多数 Agent 功能无法工作。模型失败时结构化 Analytics 仍可使用，Agent 会采用确定性模板。

## 4. 常见问题

### Web 打不开

检查 5173：

```powershell
Get-Content .runtime\logs\web.err.log -Tail 100
npm --prefix apps/web run dev
```

### Web 按钮不可用

前端要求数据库健康且 `vector_enabled=true`。检查 `/healthz`，不要只看 5173 是否监听。

### API 404

项目健康端点是：

```text
/healthz
```

不是 `/health`。

### API 可用但中文路由成 mixed

Windows PowerShell 5.1 可能用非 UTF-8 发送 JSON。使用：

```powershell
-ContentType 'application/json; charset=utf-8'
-Body ([Text.Encoding]::UTF8.GetBytes($json))
```

或使用项目内 Python/httpx。

### 数据库无法启动

```powershell
Get-Content data\postgres.log -Tail 150
.\.runtime\conda\python.exe scripts\postgres_runtime.py status
```

检查：

- 55432 是否被其他进程占用。
- `data/postgres/PG_VERSION` 是否存在。
- 项目盘是否有空间。
- PostgreSQL 是否被异常强制终止。

### pgvector 未启用

重新运行：

```powershell
.\.runtime\conda\python.exe scripts\load_data.py
```

数据库迁移会执行：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 模型不可用

```powershell
Get-Content .runtime\logs\ollama.err.log -Tail 150
.\.runtime\ollama\ollama.exe list
```

如果模型缺失：

```powershell
$env:OLLAMA_MODELS = (Resolve-Path .\models\ollama)
.\.runtime\ollama\ollama.exe pull qwen2.5:3b
```

### 模型存在但总是模板回退

检查 Trace：

```text
run.state.model_used
run.state.warnings
```

可能原因：

- 模型输出不以 `#` 开头。
- 配送报告漏掉关键卖家 ID。
- 输出包含元推理标记。
- 模型调用异常或超时。

先运行：

```powershell
.\.runtime\conda\python.exe scripts\smoke_test.py --timeout 180
.\.runtime\conda\python.exe scripts\scenario_smoke_test.py --timeout 180
```

### SSE 中断

事件保存在 `app.agent_events`，可以使用最后收到的序号恢复：

```text
GET /api/v1/runs/{run_id}/events?after=123
```

也可直接查询：

```text
GET /api/v1/runs/{run_id}/trace
```

## 5. 重建数据

### 完整重导

```powershell
.\.runtime\conda\python.exe scripts\download_olist.py
.\.runtime\conda\python.exe scripts\load_data.py
.\.runtime\conda\python.exe scripts\data_quality_report.py
.\.runtime\conda\python.exe scripts\build_knowledge.py
```

`load_data.py` 会：

- 检查 9 个 CSV。
- 对每张 RAW 表执行 TRUNCATE。
- 使用 PostgreSQL COPY 导入。
- 重建 STAGING View。
- 删除并重建 MART 物化视图。

因此不要在 RAW 或 MART 中手工保存无法再生的数据。

### 只重建知识库

```powershell
.\.runtime\conda\python.exe scripts\build_knowledge.py
```

同一内容哈希的文档会更新标题并重建其 chunks。修改内容会产生新的内容哈希；当前脚本不会自动删除所有旧版本文档，长期版本管理需要额外清理策略。

### 只生成质量报告

```powershell
.\.runtime\conda\python.exe scripts\data_quality_report.py
```

输出：

```text
data/processed/data_quality_report.html
```

## 7. 数据库人工检查

```powershell
$env:PGPASSWORD = 'olistops'
.\.runtime\conda\Library\bin\psql.exe `
    -h 127.0.0.1 -p 55432 -U olistops -d olistops
```

常用 SQL：

```sql
SELECT count(*) FROM raw.orders;
SELECT count(*) FROM mart.mart_order_fulfillment;
SELECT count(*) FROM mart.mart_payment_analysis_base;
SELECT count(*) FROM knowledge.chunks;

SELECT status, count(*)
FROM app.agent_runs
GROUP BY status;

SELECT event_type, count(*)
FROM app.agent_events
GROUP BY event_type
ORDER BY event_type;
```

## 8. 日志安全

Trace 默认对长用户输入进行截断并附加 SHA-256 摘要，但以下位置仍可能保存完整业务内容：

- `app.chat_messages`
- 最终 `assistant.delta` 事件
- 失败记录中的异常信息

不要把生产密钥、个人信息或未脱敏数据作为普通问题输入当前 MVP。

## 9. 备份建议

本地开发可备份：

- `.env.example` 和源码。
- `data/knowledge_seed`。
- `db` SQL。
- `workspace` 中需要保留的产物。

RAW 数据可以重新下载，MART 可以重建，模型可以重新拉取。`data/postgres` 若包含重要会话和 Trace，应使用 PostgreSQL 逻辑备份，而不是在数据库运行时直接复制目录。

## 10. 发布前必须完成

- 更换默认数据库密码和 `APP_SECRET_KEY`。
- 增加认证、授权和租户隔离。
- 增加 HTTPS。
- 将后台任务迁移到可靠队列。
- 增加审批 API 和写操作审计。
- 设置数据保留和删除策略。
- 将 Traceback 对外响应与内部日志分离。
- 对上传、导出和文件产物增加扫描与配额。
